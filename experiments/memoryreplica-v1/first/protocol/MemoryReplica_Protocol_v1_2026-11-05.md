**1. 이번에 답할 질문과 결론의 범위**

핵심 질문은 다음 하나입니다.

> 같은 세계에서 같은 과거 경험을 주었을 때, 성공 또는 실패 여부를 이용해 공간 정보를 보존하는 방식은 재구성한 지도에서 어떤 연결을 남기고, 후속 길찾기의 성공과 이동 비용을 어떻게 바꾸는가?

주 비교는 성공과 실패를 균형 있게 남기는 M과, 결과 구분 없이 최근 정보를 남기는 R입니다. M이 더 좋다는 가정을 두지 않습니다. 혼합 보존이 유효한 연결을 끊거나 최신 정보보다 불리할 가능성도 같은 비중으로 분석합니다.

S와 F의 비교는 필수 보조 분석입니다. 성공 출처와 실패 출처가 어떤 공간 정보를 제공했는지, 그 차이가 다음 목표에 어떻게 작용했는지 봅니다. S 또는 F의 평균이 높더라도 성공이나 실패 경험의 본질적 우월성을 주장하지 않습니다. 특정한 경험 생성 방식, 보존 용량, 목표 분포에서 나타난 정책 효과로 설명합니다.

보존 정책은 관찰 시각과 공간적 분포도 함께 바꿀 수 있습니다. 따라서 기록의 나이와 어느 지역의 길이 남았는지를 해석에 포함합니다. 이 설계는 같은 내용에 성공이나 실패라는 단어만 붙였을 때 생기는 순수한 라벨 효과를 측정하지 않습니다.

이번 연구는 선택해 전달하는 외부 기억의 효과를 측정합니다. 모델 내부의 숨은 기억, 자기보고가 실제 판단을 유발한 인과 경로, 모델 가중치의 학습 효과는 결론 범위가 아닙니다.

첨부된 [연구구성안 (1).docx](https://chatgpt.com/library?file_id=libfile_3b3fdf5f9be48191ae0b632f18df396b&account_id=personal)는 부분 관찰 아래의 단일 LLM 행위자를 생존, 관계, 경제와 장기 생활로 확장하는 상위 구상입니다. 이번 v1은 그중 기억과 후속 행동에 해당하는 제한된 하위 실험입니다. 상위 구상의 사회 시스템이나 장기 생애 구현을 이번 실험의 완료 조건으로 가져오지 않습니다.

**2. 성공과 실패, 지속형 환경의 정의**

과거 임무 하나는 시작점, 목표 장소, 최대 3개 이동으로 정의합니다. 목표에 도달하면 SUCCESS이고, 3개 이동을 마쳐도 도달하지 못하면 FAILURE입니다. 목표는 행동 실행 전에 정합니다. 현재 자료의 성공 임무는 세 번째 이동에서 처음 목표에 도달합니다.

개별 MOVE의 `SUCCEEDED`와 과거 임무의 SUCCESS는 다른 값입니다. 현재 통제 자료의 MOVE는 전부 정상 실행되지만, 임무는 절반이 실패합니다. 이것은 모순이 아닙니다. 이동 자체는 가능해도 제한된 행동 횟수 안에 목표에 가지 못한 것입니다.

환경 하나에서 4개 과거 임무를 이어서 실행합니다. 임무 사이에 캐릭터 위치를 초기화하지 않습니다. 같은 도로와 비용을 유지한 채 총 12개 이동을 수행하고, 마지막 위치에서 새 목표를 줍니다. 성공 임무 2개와 실패 임무 2개가 포함됩니다. 여섯 가지 가능한 성공과 실패의 순서는 개발 자료에서 한 번씩, 본 평가에서 열 번씩 배치했습니다.

지속형이라는 말은 이 실험에서 같은 세계와 연속된 경험을 다음 임무에 이어 사용하는 뜻입니다. 24시간 자율 생활이나 장기 사회 시뮬레이션을 완주했다는 뜻으로 사용하지 않습니다.

과거 이력은 기존 엔진으로 실행한 **통제된 스크립트 경험**입니다. 실제 LLM이 자율적으로 획득한 이력이라고 설명하지 않습니다. 기억 선택의 효과를 같은 이력에서 비교하기 위한 구성입니다. 자연스러운 LLM 경험 분포와 자기반성 학습으로의 일반화는 남는 한계입니다.

**3. 기억 단위를 고정함**

이번 기억 단위는 전체 임무 로그가 아니라, 임무 중 직접 관찰한 **방향이 있는 도로 하나의 정보**입니다. 각 기억에는 경로 ID, 출발지, 도착지, 이동 비용, 통행 가능 여부, 관찰 시각, 출처 임무 ID와 목표, 출처 임무 결과가 들어갑니다.

이렇게 구체화한 이유는 기존의 같은 토큰 상한만으로는 조건별 도로 정보 개수가 크게 달라질 수 있기 때문입니다. S, F, M, R에는 각각 중복 없는 도로 정보 4개를 제공합니다. 네 조건은 제공되는 도로 정보 수가 같고 어떤 도로가 남는지가 다릅니다. 각 도로의 표현 형식도 같습니다.

정확히 같은 토큰 수나 같은 정보 엔트로피를 보장한다는 뜻은 아닙니다. 입력 길이는 기록합니다. 이번 본 평가 입력의 아카이브 직렬화 길이는 657에서 661바이트입니다. 실제 토큰 수는 사용 모델의 요청 기록으로 확인해야 하며, 바이트 수를 토큰 수로 치환하지 않습니다.

첫 비교는 기억의 **선택 방식** 비교입니다. 같은 내용을 자연어, 그래프, 요약으로 바꾸는 표현 방식 비교는 이번 v1에 넣지 않습니다. 현재 제목은 기억 보존 방식의 분석이므로 이 범위로도 성립합니다.

| 조건 | 선택 규칙 | 아카이브 크기 |
|---|---|---:|
| N | 과거 임무의 도로 기억을 제공하지 않음 | 0개 |
| S | 성공한 임무에서 관찰한 도로 중 최신 정보 선택 | 고유 도로 4개 |
| F | 실패한 임무에서 관찰한 도로 중 최신 정보 선택 | 고유 도로 4개 |
| M | 성공 출처 2개와 실패 출처 2개를 교대로 선택 | 고유 도로 4개 |
| R | 결과 구분 없이 최신 도로 정보 선택 | 고유 도로 4개 |

공통 선택 절차는 다음과 같습니다.

1. 새 임무의 현재 관찰에 이미 나오는 도로는 과거 기억 후보에서 제외합니다. 현재 정보의 중복 때문에 기억 슬롯이 달라지지 않게 하기 위한 공통 규칙입니다.
2. 같은 경로를 여러 번 관찰했으면 각 조건의 후보 집합 안에서 최신 기록만 남깁니다.
3. 관찰 시각 내림차순, 경로 ID 내림차순으로 선택합니다. 같은 시각의 동률을 처리하는 경로 ID는 환경 생성 시 무작위로 배정합니다.
4. M은 S 후보, F 후보, S 후보, F 후보 순서로 아직 선택하지 않은 경로를 하나씩 가져옵니다. 결과적으로 각 출처에서 2개를 얻습니다.
5. 제공할 때는 관찰 시각과 경로 ID의 오름차순으로 배열합니다. 조건명 N/S/F/M/R과 연구자 평가값은 모델에게 보내지 않습니다.

선택은 새 목표를 이용하지 않습니다. 첫 입력에서 한 번 정한 아카이브를 새 임무가 끝날 때까지 유지합니다. 이후 위치가 바뀔 때마다 다른 과거 정보를 다시 검색하지 않습니다.

S나 F에 필요한 후보가 없는 세계는 입력 구성 단계에서 부적격으로 기록합니다. 실제 LLM 결과를 보고 세계를 제외하거나 다른 사례로 바꾸지 않습니다.

**4. 공통으로 유지할 조건**

- 같은 환경 내 다섯 실행은 같은 과거 이력, 시뮬레이션 시각, 시작 위치와 새 목표에서 출발합니다.
- 세계는 정적입니다. 도로 폐쇄, 재개방, 소문 오류, 상태 갱신은 넣지 않습니다.
- 모델은 기존 실행의 `gpt-5.4-mini-2026-03-17`, reasoning medium, service default를 기준으로 고정합니다. 출력 한도는 기존 8,192를 유지합니다. 실제 사용 가능 여부는 실행 연결 단계에서 확인하며 모델을 조용히 교체하지 않습니다.
- 새 임무는 최대 6개 행동과 시작 시각 이후 24틱을 허용합니다. MOVE와 WAIT만 사용합니다. WAIT도 행동 횟수를 소모합니다.
- N도 현재 관찰과 새 임무 안에서 얻은 작업 기억을 받습니다. N은 과거 임무 기억이 없다는 뜻입니다.
- 새 임무의 관찰, 실행 행동, 결과는 모든 조건에서 같은 규칙으로 누적합니다. 행동이 달라진 뒤의 실제 관찰 값이 같아야 한다는 뜻은 아닙니다.
- 모든 조건은 같은 즉시 피드백 규칙을 사용합니다. 새 임무 시작 시 `last_receipt=null`이고, 이후에는 그 임무에서 방금 실행한 행동 결과를 제공합니다.
- 추가 자기반성, 별도 요약 모델, LLM 평가자, 벡터 검색을 넣지 않습니다.
- 다섯 조건의 실행 순서는 순환 배치합니다. 본 평가에서는 각 조건이 각 순서 위치에 12번씩 오도록 합니다.

8에서 12개 장소를 가진 세 구조 계열을 사용합니다. 고리와 추가 연결, 중심 연결, 두 구역 사이 연결로 구분하며 각 세계의 연결과 비용을 생성 규칙에 따라 정합니다. 본 표본은 계열마다 20개입니다. 이는 세 생성 계열에서 얻은 60개 세계이며, 60종의 완전히 다른 환경 유형을 검증했다는 뜻은 아닙니다. 지명만 바꾼 복사본을 표본으로 더하지 않습니다.

**5. 두 가지 과제와 결과 분리**

각 조건에서 시작 입력으로 지도 재구성을 한 번 요청하고, 같은 시작 입력으로 후속 길찾기를 수행합니다. 지도 응답을 행동 입력에 넣지 않습니다. 재구성과 첫 행동 요청을 재구성 응답 전에 확정하는 기존 원칙을 유지합니다.

재구성은 경로의 출발지, 도착지, 비용, 통행 여부를 명시적인 사실로 출력하게 합니다. 현재 경로 ID에는 출발지와 도착지 이름을 넣지 않습니다. 경로는 방향이 있는 것으로 설명하며 관찰하지 않은 역방향을 자동으로 추정하도록 지시하지 않습니다.

행동 입력에는 세계 전체 그래프, 정답 경로, 조건명, 어떤 기록이 이번 목표에 유용한지에 대한 평가값이 들어가지 않습니다. 전체 JSON 파일을 모델에 보내지 않고 `contexts[조건]`의 지정된 내용만 사용해야 합니다. `world_truth`, 기준 경로와 점수는 연구자 전용입니다.

현재 데이터 묶음의 `reference_only_*` 값은 프로그램이 입력을 정확하게 읽었을 때의 기준값입니다. LLM 출력이나 LLM 성과로 표에 옮기면 안 됩니다. `model_outputs`는 모두 null입니다.

**6. 주 지표 하나와 필수 보조 분석**

주 행동 점수는 다음으로 고정합니다.

`E = 목표 도달 시 C* / C, 목표 미도달 시 0`

C는 실제 이동과 대기에 사용한 틱입니다. C*는 같은 세계에서 최대 6행동과 24틱의 제한을 지키는 최저 비용입니다. 제한 없이 계산한 경로와 비교하지 않습니다. 시작점과 목표는 다르고 적어도 두 번의 이동이 필요합니다. 따라서 성공한 실행의 C는 양수입니다.

성공과 경로 효율을 함께 평가하는 방향은 [Anderson 등의 탐색 평가 권고](https://arxiv.org/abs/1807.06757)와 [완료 시간 기반 평가 연구](https://arxiv.org/abs/2103.08022)를 참고했습니다. 여기의 E는 이 엔진의 틱과 행동 제한에 맞춘 점수이며, 원 논문의 SPL이나 SCT를 그대로 재현한 것이라고 부르지 않습니다.

주 효과는 환경별 `E(M) - E(R)`를 구한 뒤 평균한 값입니다. 주 비교는 이 하나이며, 나중에 가장 잘 나온 다른 조건 비교로 바꾸지 않습니다. 두 조건의 차이가 음수이면 M이 불리하다는 결과로 보고합니다.

실질적으로 주목할 차이의 기준은 E의 절대 차이 0.10점으로 둡니다. 이것은 성공률 10퍼센트포인트를 뜻하지 않습니다. 효과의 부호, 크기, 신뢰구간을 함께 보고하며 0.10을 실제로 관측할 것이라고 가정하지 않습니다.

0.10은 결과를 보기 전에 정한 이번 프로젝트의 실질적 차이 기준이며 학계의 보편적 기준은 아닙니다. 통계적으로 구분돼도 이보다 작은 차이라면 작은 효과라고 설명합니다.

| 분석 | 정의와 해석 |
|---|---|
| 실제 세계와의 경로 속성 일치 F1 | 경로 ID, 출발지, 도착지, 비용, 통행 상태가 정확히 맞는 경로를 계산. 틀린 연결과 누락을 함께 반영 |
| 전체 경험에서 관찰한 범위 | 실제 세계 중 경험에 들어온 정보. 한 번도 보지 않은 정보를 기억 실패로 부르지 않음 |
| 선택 단계에서 남긴 경로와 빠진 경로 | 원래 경험에서 알 수 있었지만 선택 때문에 사라진 정보 |
| 입력 조건부 복원 | 제공된 경로 정보를 정확히 복원했는지. 의미 오류와 출처 주소 오류를 구분 |
| 목표까지 연결되는 경로 | 입력 기준 그래프와 모델이 복원한 그래프에 각각 경로가 있는지, 그 비용이 얼마인지 |
| 실제 길찾기 | 성공률, 비용, 행동 수, 유효하지 않은 행동, 주 점수 E |
| S와 F의 차이 | 출처 집단의 정보가 어떤 목표에서 도움이 되거나 부족했는지 |

목표 연결성 분석은 필수입니다. 같은 수의 정확한 도로를 복원하면 전체 지도 F1은 같아질 수 있지만, 남은 도로의 조합에 따라 목표에 도달할 경로가 없어질 수 있습니다. 전체 지도 점수만으로 기억의 유용성을 대신하지 않습니다.

모델이 말한 경로로 연결성을 계산할 때는 존재하지 않는 도로나 잘못된 속성으로 만든 가짜 경로를 정답으로 인정하지 않습니다. 모델 주장 그래프의 계획과 실제 세계에서 검증한 유효한 계획을 구분합니다. 전자는 잘못된 믿음, 후자는 실제 사용 가능한 경로를 보여줍니다.

반복 실패는 같은 오류를 다시 범할 기회가 있는 사례에서만 보조 분석합니다. 후속 목표가 과거 실패 목표와 다를 수 있으므로 모든 실행을 반복 실패 실험으로 부르지 않습니다. 단순한 재방문도 탐색이나 복귀일 수 있어 무조건 오류로 세지 않습니다.

**7. 실제로 끝낸 입력 및 엔진 검증**

`validate_design.py`는 기존 JourneyMap의 MovementModule, 관찰 파이프라인과 행동 실행기를 가져와 사용합니다. 새 세계 엔진을 만들지 않았으며 원래 Python 소스 147개는 변경되지 않았습니다.

| 항목 | 개발 자료 | 본 평가 자료 |
|---|---:|---:|
| 환경 수 | 6 | 60 |
| 과거 임무 수 | 24 | 240 |
| 채택된 과거 이력의 엔진 MOVE 수 | 72 | 720 |
| 조건별 시작 입력 수 | 30 | 300 |
| 실제 LLM 요청 수 | 0 | 0 |
| 성공과 실패 순서 6종의 빈도 | 각각 1회 | 각각 10회 |

세계별 두 성공과 두 실패 임무, 네 조건의 고유 경로 4개, 공통 현재 관찰과 목표, 혼합 출처 비율, 중복 제거, 의미와 출처 점수 분리를 확인했습니다. 개발과 본 자료의 세계 서명도 겹치지 않습니다. 원래 실행기의 제한을 고려해 기준 경로 계산에도 6행동과 24틱을 적용했습니다.

생성 규칙을 충족하지 못한 후보는 개발에서 1개, 본 평가에서 8개였고 모두 사유를 기록했습니다. 주된 사유는 최대 3이동의 과거 임무 구성을 만들 수 없다는 것이었습니다. 본 자료 중 한 후보는 이미 접한 비인접 목표를 만들 수 없었습니다. 이는 모델 성과에 따른 제외가 아니며 본 평가의 추론 범위도 이 입력 적격 조건을 만족한 세계로 제한됩니다.

검증에서 얻은 유용한 반례는 다음과 같습니다.

| 본 평가용 입력의 기준 경로 연결성 | 세계 수 |
|---|---:|
| M과 R 모두 완성된 경로 근거가 있음 | 22 |
| R에만 있음 | 9 |
| M에만 있음 | 1 |
| 둘 다 없음 | 28 |

M과 R의 기억 도로 집합이 같은 세계도 20개 있습니다. 이 사례를 차이가 작다는 이유로 제거하지 않습니다. 두 정책이 같은 기억을 선택하는 빈도 역시 정책 비교의 일부입니다.

모든 본 세계에서 S, F, M, R에 제공되는 도로 개수가 같으므로, 그 정보를 완벽하게 복사한 기준 지도의 F1도 같습니다. 그러나 완성된 경로 근거가 있는 세계 수는 S 28, F 20, M 23, R 31개로 다릅니다. 이것은 **입력의 구조적 성질**이며 AI의 도착 횟수나 성공률이 아닙니다. 경로 근거가 없는 조건도 새 관찰을 얻으며 목표에 도달할 수 있습니다.

이 결과 때문에 혼합 보존의 우월성을 연구의 예정된 결론으로 두지 않습니다. 실제 모델이 이러한 정보 차이를 그대로 따르는지, 복원 과정에서 더 잃는지, 새로운 탐색으로 보완하는지가 실제 LLM 실험의 관찰 대상입니다. 모든 차이가 입력 기준만으로 설명되면 그 범위로 결론을 제한하고, 새로운 인지 능력을 발견했다고 주장하지 않습니다.

**8. 규모와 분석을 고정함**

개발은 6개 환경에서 5조건을 한 번씩, 본 평가는 별도의 60개 환경에서 5조건을 한 번씩 실행합니다. 본 평가의 총 실행 수는 300개입니다. 이전 검토 보고서의 48환경에 두 반복을 붙이는 480개 후보 대신, 반복보다 독립 환경을 우선하는 구성을 택했습니다.

한 환경의 5조건을 대응시킵니다. 기본 분석 단위는 환경이고 호출 수, 과거 이동 수, 복원 사실 수를 표본 수에 더하지 않습니다. 단일 실행의 출력 무작위성이 환경별 차이에 포함됩니다. 같은 세계에서의 출력 분산을 별도로 충분히 추정하는 설계는 아닙니다.

주 효과의 95% 신뢰구간은 세 환경 계열 안에서 세계를 재표집하는 층화 대응 부트스트랩으로 계산합니다. 각 계열의 비중은 1/3, 재표집 수는 20,000, 분석 난수 시드는 20261105로 고정합니다. S/F 등 나머지 비교는 보조 분석임을 표시하고 유리한 비교만 골라 확증 결과처럼 제시하지 않습니다.

정규 근사로 평균 차이 0.10점을 가정하면, 대응 차이의 표준편차가 0.25일 때 n=60의 근사 검정력은 약 87%이지만 0.40이면 약 49%입니다. 실제 효과와 표준편차를 측정한 값이 아니며, 제한되고 비정규적인 점수 분포에서 이 근사는 정확하지 않을 수 있습니다. 60개라는 숫자가 충분함을 보장하지 않습니다.

본 평가가 시작되면 표본을 늘리지 않습니다. 구간이 넓으면 불확실한 결과로 보고합니다. 모든 차이가 0인 경우 부트스트랩 구간이 0폭으로 나오는 것을 모집단의 완전한 동등성 증거로 사용하지 않습니다.

한 실행은 지도 요청 1회와 행동 요청 최대 6회입니다. 본 평가의 상한은 2,100요청, 최초 개발 실행까지 합하면 2,310요청입니다. 개발의 기술적 보완 뒤 전체 개발 자료를 한 번 더 확인하는 최악의 경우까지 포함하면 최대 2,520요청입니다. 이것은 호출 수 상한이며 금액 승인이나 실제 요청 완료 수가 아닙니다.

유료 실행 비용 상한은 기존 소진 배치의 승인을 재사용하지 않고 실제 실행 계획에서 정해야 합니다. 이 문서는 설계와 오프라인 자료를 확정하며 API 호출을 실행하지 않습니다. 현재 단계에서 부족한 것은 기억 질문의 추가 확장이 아니라 기존 실행 연결과 실제 비용 확인입니다.

**9. 실패와 누락을 처리하는 규칙**

모델이 잘못된 행동 형식을 내거나 출력 한도로 유효한 행동을 만들지 못한 경우, 그 실행의 운용 성과에 반영하고 유형을 별도로 기록합니다. 그런 기록을 과거 임무 실패 기억으로 새로 넣지 않습니다. 엔진이 거절한 행동도 행동 기회 하나를 소모합니다.

외부 API 장애나 전송 불확실성 때문에 결과를 모르면 그것을 목표 실패 0점으로 임의 변환하지 않습니다. 기존 실행기의 전송 및 원장 처리 규칙을 재사용합니다. 누락이 해결되지 않으면 불완전한 배치라고 표시하고, 조건마다 다른 표본을 사용해 완전한 대응 비교처럼 보고하지 않습니다. 이번 연구 때문에 별도의 감사 플랫폼을 추가하지 않습니다.

유효한 결과가 불리하게 나왔다는 이유로 재실행하지 않습니다. 실행 후 표본 교체, 목표 변경, 기억 용량 변경, 추론 강도 변경은 v1 결과에 섞지 않습니다.

**10. 남은 구현과 종료 조건**

검토에서 기존 E04의 `semantic_input()`이 장소 이름 S/A/B/C/D/G를 고정 검증한다는 점도 확인했습니다. 새 환경을 실행하려면 runner 인자만 추가하는 것으로는 부족합니다. 기존 E04 코드를 보존하고, MemoryReplica용 입력 변환기를 작은 별도 경로로 구현해야 합니다.

남은 구현은 다음 네 묶음으로 제한합니다.

| 작업 | 완료 판단 |
|---|---|
| 새 관찰과 기억 입력 연결 | 저장된 `contexts`와 같은 규칙으로 모델 입력이 만들어지고 연구자 전용 값이 들어가지 않음 |
| 기존 실제 호출 연결 재사용 | 새 환경의 끝 상태에서 시작하고 현재 임무 작업 기억과 즉시 결과를 공통 규칙으로 제공 |
| 복원 평가 연결 | 기존 사실 응답을 경로별로 묶어 의미, 출처, 입력 손실, 경로 연결성을 분리해 계산 |
| 결과 집계 | 300개 실행의 모든 상태를 반영해 주 효과와 필수 보조 결과를 한 번에 출력 |

새 GUI, 그래프 데이터베이스, 사회 시스템, 환경 변화, 모델 교체 비교, 추가 기억 방식, 자동 자기반성은 v1의 필수 작업이 아닙니다. 기존 F1 조사나 전체 저장소 hardening을 연구 선행조건으로 다시 열지 않습니다. 다만 이번 실행에서 실제로 재현된 관련 오류는 영향 범위만 수정합니다.

목표 작업 시간은 구현 2작업일, 개발 실행과 필요한 기술적 보완 1작업일, 본 실행 1배치, 분석과 결과표 2작업일입니다. 달력상 자동 실행이나 납기 보장을 설정한 것은 아닙니다. 구현이 이 범위를 넘으면 기능을 추가하는 대신 어떤 연결이 막혔는지와 최소 수정 범위를 기록합니다.

개발 결과가 모두 비슷하거나 M이 불리하다는 이유는 과제 난도와 프롬프트를 반복 조정할 이유가 아닙니다. 개발에서 고칠 것은 형식 오류, 입력 혼입, 채점 오류 같은 기술적 문제이며 보완 기회는 한 번으로 제한합니다. 실제 모델에 기본 지도를 복원할 능력이 없어 평가가 성립하지 않는다면 그 상태를 보고하고 본 실행을 시작하지 않습니다.

v1은 다음 네 산출물이 나오면 종료합니다.

1. 조건별 실제 성과와 M-R 차이 및 신뢰구간.
2. 보존 손실, 복원 오류, 행동 손실을 연결한 표.
3. 같은 노드 배치에서 실제 지도, 보존된 지도, 모델 복원 지도, 실제 경로를 보여주는 사례 그림.
4. 주장 가능한 범위와 반대 결과, 무차이 결과, 자료 한계를 포함한 보고서.

M의 우월성, 유의확률 기준 통과, 새 기억 알고리즘의 개발은 완료 조건이 아닙니다. 오류 원인에 맞는 개선 실험은 v1 보고 이후 별도 결정으로 분리합니다.

**11. 방향 이탈을 판별하는 간단한 기준**

새 작업을 추가하려면 다음 문장을 채울 수 있어야 합니다.

> 이 작업은 성공 및 실패 출처의 공간 기억 선택이 ______에 미치는 영향을 평가하는 데 필요하며, 완료되면 결과표의 ______가 채워진다.

채울 수 없다면 이번 필수 범위에 넣지 않습니다. 예외는 실제로 관측된 실행 오류를 고치는 최소 수정입니다. 이 기준을 위한 별도 승인 서비스나 관리 시스템은 만들지 않습니다.
