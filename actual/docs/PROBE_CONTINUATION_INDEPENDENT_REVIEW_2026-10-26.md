## 3. 코드 판단

### 관측의 의미와 비밀정보

연결 객체 생성, request, 응답 헤더, 본문, framing, JSON, secret scan, runner와 credential 경계를 구분한다. HTTPSConnection 생성만으로 DNS/TCP/TLS 성공을 주장하지 않는다. request 내부의 연결 세부 단계는 이번 구현의 관측 범위 밖이다.

예외 분류는 isinstance와 고정 허용 목록을 사용한다. timeout, DNS, TLS 및 RemoteDisconnected 같은 하위 타입이 광범위한 OSError에 가려지지 않는다. 동적 클래스 이름, 메시지, args, traceback이나 IncompleteRead.partial을 진단에 기록하지 않는다. 가짜 비밀을 넣은 테스트와 허용되지 않은 필드 거부가 통과했다.

### 기록 결합과 실패 시 중단

진단은 RESPONSE 또는 NOT_SENT의 필수 필드로 journal에 결합한다. run, request, body digest, event, ordinal과 버전을 검사한다. 진단 누락, 추가 필드, 다른 요청 대입, 허용 목록 밖 값, framing 및 HTTP 상태 모순, 완료 시간 모순을 거부한다. hash chain을 재계산한 반례도 거부한다.

이 검증은 신뢰된 로컬 관측의 구조와 일관성을 검사한다. 공격자가 코드와 승인 및 journal 전체를 바꾸는 상황에서 네트워크 사건의 진위를 독립 인증하는 것은 아니다. 계약도 이 한계를 명시한다.

진단이 없는 실제 transport 응답에 정상 진단을 대신 붙이지 않는다. 모의 recording 경로만 명시적 RECORDED를 사용한다. 저장 실패 전후 및 commit 직후 예외에서는 후속 전송을 하지 않고 마지막 확정 prefix를 OPEN으로 유지한다. 예약을 지우거나 성공 상태로 보정하지 않는다. OSError와 SQLite 오류는 원문 대신 고정 문구로 노출한다.

### 기존 수신 및 회계 경계

하위 TimeoutError, 부분 수신 deadline, 완전히 받은 늦은 응답을 구분한다. 완전한 늦은 응답은 기존 classifier가 usage를 회수하면서 엔진에는 전달하지 않는다. PE-R1 framing 검사, 2,000,000-byte 수신 한도, 깊은 JSON 및 UTF-8 경계가 관련 테스트에 포함돼 통과했다.

진단만으로 미전송 또는 무과금을 확정하지 않는다. 전송 후 원문을 확보하지 못한 경우 예약 유지와 총비용 미확정을 보존한다. runner fallback의 0ms는 실제 지연으로 평균에 넣지 않으며 해당 요청 자체는 오류 및 계획 분모에 남긴다.

v2는 옛 binding과 v1 registry marker를 거부한다. v1을 자동 변환하거나 현재 source로 과거 승인을 재봉인하지 않는다. 과거 report는 a362 runtime으로 계속 감사할 수 있다. v2 통과가 v1 운영 DB의 새 실행 차단을 해소하는 것은 아니다.

## 4. 회계 정책 초안 판단

**초안의 방향은 타당하나 운영 적용이나 구현 통과 판정은 아니다.** 증거 기반 회계 확정과 미확정 노출을 감수한 후속 연구를 분리한 점이 중요하다.

현재 없는 것은 17번째 요청에 귀속되는 원본 응답과 usage 또는 권위 있는 요청별 정산 근거다. 이번 검토에서도 이를 확보하지 않았다. 전체 계정 합계나 새로 실행한 요청의 결과로 원본의 비용을 채울 수 없다. 초안에 인용된 공개 API 문서를 이번 검토에서 새로 확인하거나 실제 계정을 조회한 것은 아니다.

연구를 계속할 경우 권고하는 설계 방향은 다음과 같다. 아래는 사용자 정책 판단 후 구현하고 검토할 사항이며 현재 승인된 운영 정책이 아니다.

1. 기존 UNCERTAIN, 원래 예약, 원문 및 소비 run/approval ID를 유지한다.
2. 원본 v1 이력과 새 v2 이력을 연결한 단일 운영 이력 원장을 두고, 알려진 비용과 미확정 노출을 분리한다.
3. 후속 실행의 조건부 누적 예산에 과거 확인 비용과 미확정 노출을 포함한다. 이전 요청의 총비용을 숫자로 확정하지 않는다.
4. 단일 운영 기기와 단일 writer, 이력 인수, 만료 및 일회성 승인, 중복 claim 방지를 구현한다. 새 DB를 만들기만 해서 원래 차단을 우회하지 않는다.
5. 이력 누락, stale hash, 잘못된 기기, 소비 ID 재사용, 동시 claim, commit 전후 저장 실패를 키 조회 전에 차단하는 반례 검증을 수행한다.

로컬 파일을 신뢰하는 설계에서 모든 보존본을 일관되게 과거로 되돌린 공격까지 hash만으로 탐지할 수 있다고 주장해서는 안 된다. 구현 시 신뢰하는 최신 이력 기준점과 다른 기기 실행 금지 전제를 명시해야 한다. 이는 초안의 로컬 운영 신뢰 경계를 구체화할 후속 요구사항이다.

현재 원본 registry에 새 claim을 허용하는 정책은 없다. 초안의 위험 수용 대안 채택 여부와 누적 예산은 사용자 판단이 남아 있다. 그다음 필요한 구현, 반례 검증 및 독립 검토를 마치고 정확한 실행안을 작성해야 한다. 이번 지적은 제출 범위가 초안이라는 전제에 따른 후속 조건이며 진단 구현의 새 결함 판정이 아니다.

## 5. 예산과 분석 기준 판단

제출된 산술과 실제 Ledger의 모의 경계 검증은 일치한다. 현재 US$1.00, 입력 500,000, 출력 589,824 한도는 변경되지 않았다. US$3.03과 US$24.26 설정은 현재 ProbePlan에서 여전히 거부된다.

| 검토안 | 코드 비용 한도 | 입력 누적 한도 | 핵심 제한 |
| --- | ---: | ---: | --- |
| 현재 | US$1.00 | 500,000 | 최대 출력이 이어지면 비용으로 조기 중단 가능 |

72개 출력 최대치의 비용은 고정 단가로 US$2.654208이다. 입력 500,000까지 더한 비용은 US$3.029208이지만, 각 요청 시작 전에 입력 400,000을 예약해야 하므로 US$3.03만 올려서는 입력 gate를 해결하지 못한다. 합성 입력 1,500, 출력 100의 현재 trace도 67회에서 입력 한도로 중단한다.

이론 후보는 72 × (400,000 입력 + 8,192 출력)의 고정 단가 비용 US$24.254208에서 나온다. 네트워크 성공, 제공자 수락, 오류 없는 72회 완료나 외부 청구의 무조건 상한을 보장하지 않는다. 이 예산만큼 실제로 사용할 것으로 예측하는 계산도 아니다. 실제 예산 선택은 별도로 해야 한다.

과거 확인 비용과 유지 예약의 검토용 합은 US$0.45731985다. 이를 포함한 조건부 계획 노출은 US$3.03 후보에서 US$3.48731985, US$24.26 후보에서 US$24.71731985다. 원래 예약을 실제 비용으로 바꾸거나 청구 상한으로 표현하지 않는다.

사전 분석 계획은 원래 12사례 × 3조건 × 2반복을 유지한다. 조건별 계획 분모, usage 공통 집합과 행동 공통 집합, 반복 차이, 순서 및 cache 한계를 분리한다. 실패와 미실행을 삭제하지 않으며 엔진 성공을 행동 품질이나 24시간 생존으로 해석하지 않는다. 과거 부분 실행과 다음 배치를 기본적으로 분리하는 것도 적절하다. 모의 72슬롯 통과는 연구 효과의 실제 측정치가 아니다.

이번 검토를 다시 요청하기 위해 같은 ZIP을 재생성할 필요는 없다. 데스크톱에서는 현재 source가 912eb145 전체 identity와 일치하는지 읽기 전용으로 대조하고 이 검토서를 기존 완료 자료에 연결하면 된다. 그 과정에서 운영 DB, 기존 승인 및 실행 자료는 변경하지 않는다.

다음 판단은 **원본 미확정 상태를 유지한 위험 수용 방식으로 후속 연구를 준비할지**, 그리고 **새 실행의 비용 및 입력 한도를 어떻게 정할지**다. 기존 지시는 이 정책을 초안으로만 작성하도록 제한했으므로 이번 검토 통과를 정책 채택이나 지출 승인으로 해석하지 않는다.

정책 방향 선택 → 필요한 이력 및 예산 구현과 오프라인 검증 → 후속 독립 검토 → 정확한 source/이력/계획을 결합한 실행안 → 사용자 실행 승인 → 실제 수집 및 무재호출 감사 → 조건별 분석과 전반부 보고 순서다. 일정에 맞추려고 원래 72슬롯이나 검증 과정을 줄이지 않는다. 중단 또는 차이 없음도 기록과 해석을 마친 결과로 보고한다.

## 7. 독립 검토 근거 파일

프로젝트 내 근거 폴더: `artifacts/probe-continuation-review-2026-10-26/`

- `package-verification.json`: ZIP payload 및 before 파일 대조.
- `independent-tests.log`, `independent-tests.xml`: 283개 테스트 결과.
- `independent-ruff-check.log`, `independent-ruff-format.log`, `independent-mypy.log`: 독립 정적 검사.
- `independent-evidence-verification.json`: 두 source와 corpus 비교, 보고서 5종의 별도 프로세스 감사 결과 및 hash.
