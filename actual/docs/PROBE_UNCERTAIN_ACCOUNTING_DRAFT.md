아래 US$3.03은 과거 예시이며 이번 구현 후보는 별도 plan의 US$24.26/누적 US$24.71731985다.

## 현재 사실과 기본 동작

run 2f781fd7-99c8-47f2-a4f1-77c5c6a1420b는 UNCERTAIN, 확인 비용 120,455,850 nano-USD,
유지 예약 336,864,000 nano-USD, 총비용 null이다. 17번째 요청은 HTTP 상태/응답 ID/원문/usage가 없다.
원래 예약은 보고 usage·신원·단가에 관한 조건부 보호값이며 실제 청구 또는 외부 청구의 무조건 상한이 아니다.
근거가 없으면 이 상태와 새 claim 차단을 그대로 유지한다. 예약 0, FINISHED 변경, guard 삭제나 빈 DB 우회는 대안이 아니다.

## 증거에 근거한 확정 경로 — 설계 제안

요청과 연결 가능한 원본 제공자 응답/usage 또는 특정 요청에 귀속되는 권위 있는 정산 증거가 필요하다.
대상 run/request/body digest, 계정·기간·endpoint/model 범위, 제공자 request/response 식별자와 근거 출처를 연결하고
동일 요청임을 입증해야 한다. 전체 계정 사용량 증가나 결제 합계만으로 이 요청의 usage·무과금을 확정하지 않는다.

[공식 조회 API](https://developers.openai.com/api/reference/python/resources/responses/methods/retrieve)는 response_id를 요구한다.
[공식 데이터 제어 문서](https://developers.openai.com/api/docs/guides/your-data)의 저장/보존 설명도 확인했다(2026-10-26).
response_id가 없고 store=false인 현재 요청을 이 API로 회수할 수 있다고 확정할 근거는 없다.
공개 문서 확인과 실제 계정 조회는 다르며 이번에는 API GET·계정 접근·지원 문의를 하지 않았다.
저장되지 않은 자료의 회수 가능성이나 무과금을 반복 확인하도록 요구하지 않는다. 현재 구체적으로 없는 것은
**17번째 요청에 귀속되는 응답 ID/usage 또는 권위 있는 요청별 정산·미과금 증거**다.

증거가 확보되더라도 원본 journal/report/승인은 보존하고 별도 append-only reconciliation 기록을 제안한다.
그 기록에는 policy/version, 원본 DB/report/entry hash, 대상 run/request/body, 증거 해시·출처·범위,
재계산 가능한 usage와 고정 rate card 또는 정산 금액·통화·근거, 작성 주체/시각·검토·별도 승인 ID를 둔다.
사용량 확정과 최종 청구 금액 확정은 별개로 표시한다. 원본 응답 없는 synthetic usage나 재호출 응답을 원본으로 채우지 않는다.

검증기는 원본 prefix/대상 결합, usage의 정수·부분집합/합, 신원/단가 범위와 금액 계산을 검증해야 한다.
원본 대상+증거 ID의 고유성, 이미 적용한 대상의 중복 정산/충돌 수정 방지, 후속 정정의 명시적 supersedes 체인,
hash 재계산만 한 변조와 비용을 낮춘 위조를 거부해야 한다. 검토자와 사용자 승인 뒤 원본과 overlay의 재계산을 비교하며
새 claim 허용 여부도 별도로 결정해야 한다. 원본 상태를 고쳐 과거에 확정됐던 것처럼 보이게 하지 않는다.

## 근거 미확보 시 대안 — 위험 수용과 비용 확정을 구분

기본값은 계속 차단이다. 연구를 이어갈 별도 위험 수용 정책을 검토할 수 있으나 비용 확정이나 예약 면제가 아니다.
제안 가능한 설계는 원본 v1 이력과 향후 v2 이력을 연결한 **단일 권위 이력 원장**에서 다음을 원자적으로 관리하는 방식이다.

1. 알려진 비용과 미확정 예약/노출을 분리하고, 원래 UNCERTAIN과 총비용 null을 유지한다.
2. 모든 과거 소비 run/approval ID와 원본 registry hash·위치를 연결한다. protocol/기기/DB가 달라도 소비 ID 재사용을 막는다.
3. 후속 run의 요청별 예약과 과거 노출을 합친 검토용 누적 예산을 따로 검사한다. 외부 청구 상한이라는 표현은 쓰지 않는다.
4. 별도 위험 수용 승인에 대상 불확정 요청, 현재 조건부 노출, 후속 실행 범위/예산, 적용 주체·일회성·만료·동시 실행 금지를 결합한다.
5. 이력 인수 없는 다른 기기/빈 원장을 거부한다. 한 운영 기기·단일 writer와 영속 claim/잠금을 전제로 하며,
   다른 기기로 옮기려면 기존 이력을 먼저 인수해야 한다. 다중 기기 분산 실행을 이번에 구현하지 않는다.
6. 원장 저장/조회 실패, history 누락, stale hash, 이미 소비한 ID, 불확정 승인 범위 초과 시 키 조회 전에 차단한다.
7. 차단 해소는 원본 DB의 guard를 삭제하는 방식이 아니라, 새 정책이 허용하는 한정된 claim과 미해결 이력을 함께 검증하는 방식이어야 한다.

현재 확인 비용+유지 예약의 검토용 합은 US$0.45731985다. 이는 청구 확정액도 무조건 최대 손실도 아니다.
새 예산 후보 US$3.03을 검토한다면 이 합까지 포함한 조건부 누적 계획 노출은 US$3.48731985다.
더 큰 후보도 같은 방식으로 과거 미확정 노출을 계속 명시해야 하며 자동 예산 확대는 없다.

필수 반례 검증에는 다음이 포함돼야 한다: 누락/위조/다른 요청 증거, 계정 합계만 있는 경우, 중복 정산과 상충 정정,
옛 DB로 되돌림/새 DB 우회/다른 기기 동시 claim/소비 ID 재사용/노출 누적 누락, 승인 범위 변경,
저장 실패와 commit 전후 중단. 회계 확정 경로와 위험 수용 경로의 분리도 검증해야 한다.

## 검토와 사용자 판단이 필요한 지점

- 요청별 권위 있는 증거가 실제로 없는 현재 상태에서는 증거 기반 확정 경로를 적용할 수 없다.
- 위험 수용 대안을 허용할지, 허용한다면 누적 예산과 조건부 노출·운영 주체·유효 범위를 사용자가 별도로 판단해야 한다.
- 그 정책을 독립 검토하고 필요한 구현/반례 검증을 마치기 전에는 새 실행안·실제 후보·사람 승인 파일을 만들지 않는다.
- 진단 구현 검증의 통과와 운영 차단 해소는 다른 판정이다. 이번 작업은 후자를 통과한 것으로 표시하지 않는다.
