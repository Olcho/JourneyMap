# Actual 비교 실험 분석·연구 종료 기준

2026-10-26. 다음 실제 수집 전에 유지할 분석 기준이다. 이번 변경은 prompt/평가 기준을 바꾸지 않는다.
기존 17시도 부분 실행은 탐색 배치로 보존한다. 새 수집을 허가하거나 원래 run을 재개하는 문서가 아니다.

## 설계·분모·원본

- 12개 고정 합성 사례, high_baseline/medium_baseline/medium_structured, 각 두 반복, 조건당 24슬롯, 전체 72슬롯.
- 같은 관측/고정 순서와 schema, 출력 8,192, tier/store를 유지한다. high와 medium은 effort 비교,
  medium_structured는 medium에 짧은 판단 순서를 더한 조건이다.
- 요청 원문/digest/순서, 원시 응답 또는 미확보, journal/진단, 실제 source/plan, 회계와 engine branch 결과를 보존한다.
- 조건별 시도·READY·INCOMPLETE·REFUSAL·각 오류·미실행을 전체 계획 분모와 함께 보고한다.
  실패를 삭제해 성공률을 만들거나 실패를 성공할 때까지 대체하지 않는다.
- engine SUCCEEDED/REJECTED/FAILED/INVALID_CANDIDATE, 선택한 action_type과 정규화 payload를 구분한다.
  같은 행동률은 완전히 같은 정규화 행동의 비율로 정의하며 엔진 성공·전략 최적성·장기 생존과 동일시하지 않는다.

## token·지연·비용

usage가 확인된 입력/출력/추론/cached token을 각각 보고한다. 추론은 출력의 부분집합이다.
usage 미확보 수와 미확정 비용·유지 예약을 별도 열에 두며 0으로 대체하지 않는다.
조건별 총합과 usage가 확보된 요청 수, 전체 계획 분모를 동시에 표시한다.
고정 rate card 환산 비용과 실제 청구 인증은 구분한다.

지연은 수신 완료 시각 기반 elapsed와 관측 수를 함께 보고하고, 완료·오류·부분 수신/timeout을 분리한다.
RUNNER 경계 fallback의 packet elapsed=0은 관측된 0ms 지연이 아니다. 지연 평균/비교에서는 미관측으로 처리하고
그 요청을 시도/오류/전체 분모에서 빼지 않는다. HTTP 연결 객체 생성은 DNS/TCP/TLS 성공의 증거가 아니다.

## 대응 비교와 반복

- 같은 (case_id, repeat) 세 조건의 공통 집합을 표시한다. 전체 계획 분모와 공통 집합 분모를 함께 보고한다.
- usage 공통 집합과 READY/행동을 비교할 수 있는 공통 집합은 구분한다. 공통 집합에서 제외된 이유와 개수도 유지한다.
- 조건별 token 합계 차이만으로 효과를 결론내리지 않는다. 개별 대응 쌍의 차이, 상황별 결과와 반복 1/2 편차,
  조건별 표본 불균형, 요청 순서/cache 차이를 함께 제시한다.
- medium_structured의 입력 추가와 cache 사용 차이도 명시한다. 불완전 수집의 조건별 총합을 동일 표본 비교로 표시하지 않는다.
- 합성 상황 12개/두 반복을 독립적인 세계 72표본으로 해석하지 않는다. 엔진 성공을 행동 품질이나 24시간 완주로 바꾸지 않는다.
- 결과를 본 뒤 유리한 상황·평가 지표·종료 시점을 선택하지 않는다. 예산/정확성/오류 gate는 사전 정의대로 적용한다.

## 과거 부분 실행과 후속 배치

기존 run의 17시도/16 READY/1 UNCERTAIN/55 미실행을 그대로 탐색 결과로 둔다.
새 실행은 72개 입력 전체의 별도 배치이며 16개 응답을 재사용하지 않는다. 기본 보고는 배치별로 분리한다.
합산이 필요한 경우 동일한 세계/관측의 반복 자료 구조와 배치·수집 시각/source 차이를 명시해야 한다.
미확정 요청을 재호출한 결과로 원본 usage/응답을 채우지 않는다.

## 연구 종료와 전반부 보고 순서

1. 진단 구현과 필요한 오프라인 검증.
2. 미확정 회계 정책 검토와 독립 검토의 필수 지적 해소.
3. 정확한 새 source/계획/이력/예산을 결합한 실행안.
4. 사용자 승인 후 실제 실행과 사전 중단 조건 적용.
5. 원본 보존·새 프로세스 무재호출 감사·조건별 결과와 한계 분석.
6. E03/E04 완료 결과와 Actual 확장 결과를 구분한 전반부 보고.

일정 때문에 이 순서를 축소하지 않는다. 72슬롯 시도를 목표로 하되 오류/예산 gate를 무시하지 않는다.
새 실행이 멈추면 원본과 중단 이유를 보고하고 원인 검토 없이 추가 실행하지 않는다.
중단이나 차이 없음도 기록과 해석을 마치면 연구 결과다. 필수 정확성 결함은 통과로 표시하지 않는다.
추가 모델 비교·24시간 생활 완주·기억 선택 구현은 이번 연구 종료의 조건으로 추가하지 않는다.
