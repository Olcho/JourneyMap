# 72슬롯 유지 기준 예산·admission 검토

2026-10-26. **계산 및 후보 정책 검토이며 실제 지출 승인이나 활성화된 계획이 아니다.**
현재 ProbePlan의 US$1.00/입력 500,000/출력 589,824와 요청당 입력 예약 400,000을 변경하지 않았다.
단가와 최대치 이외의 미래 입력 token 추정을 실제 usage나 검증된 상한으로 사용하지 않는다.

## 유지한 실험과 단가

12개 합성 상황 × 3조건 × 2반복 = 72슬롯, 고정 요청 본문/순서/effort/schema/출력 8,192를 유지한다.
기존 실제 16개 응답을 다음 실행의 응답으로 재사용하지 않는다. 후속 실행은 재개가 아니라 별도 배치이며,
미확정 이력 정책과 독립 검토를 먼저 충족해야 한다. 이번에는 새 실제 후보나 승인 파일을 만들지 않았다.

[공식 모델 페이지](https://developers.openai.com/api/docs/models/gpt-5.4-mini)를 2026-10-26 확인했다.
gpt-5.4-mini-2026-03-17과 default endpoint 계획의 고정 단가는 입력 750/cached 75/출력 4,500 nano-USD/token이다.
이는 공개 문서와의 대조이며 계정별 접근/청구 확인은 아니다. 추론 token은 출력의 부분집합으로 비용에 한 번만 포함한다.

## gate와 계산

한 요청의 보수적 비용 예약 R = 400,000 × 750 + 8,192 × 4,500 = **336,864,000 nano-USD**.
다음 요청은 미해결 예약이 없고 다음 조건을 모두 만족해야 한다.

- 시도 수 < 72.
- 이미 사용한 입력 + 400,000 ≤ 500,000. 따라서 요청 시작 직전 누적 입력은 **100,000 이하**여야 한다.
- 이미 사용한 출력 + 8,192 ≤ 589,824.
- 알려진 비용 + R ≤ 1,000,000,000.

다음 슬롯 예산에는 실제 다음 usage가 아니라 R 전체가 들어가야 한다. 최종 합계가 예산에 들어간다는 계산만으로
그 앞선 admission을 보장할 수 없다. 미확정 응답은 예약을 해제하지 않으므로 다음 슬롯을 막는다.

- 72 × 8,192 = **589,824 출력 token**, 출력 비용만 **US$2.654208**.
- 입력 총 500,000을 전부 non-cached로 계산한 비용과 더하면 **US$3.029208**.
- 72번 모두 입력 예약 상한 400,000을 소모하는 코드 허용 극단의 입력 합은 **28,800,000**.
  이때 요청별 예약 72배 = 총 입력/출력 비용 = **US$24.254208**.

입력 cap L, 출력 cap 589,824에서 72번째를 시작하려면 과거 입력 ≤ L − 400,000이어야 한다.
최대 과거 비용 + 마지막 예약 = (L − 400,000) × 750 + 71 × 8,192 × 4,500 + R
= L × 750 + 589,824 × 4,500이다. 이 식은 **입력 gate를 통과한 trace**와 고정 신원/usage/단가를 전제로 한
비용 계산이다. 입력 gate 통과, HTTP 성공, 제공자 schema/context 수락이나 외부 청구 차단을 보장하지 않는다.

## 실제 동결 Ledger의 명시적 모의 trace

아래 token은 테스트에서 지정한 합성 usage다. 미래 요청 token 예측도 실제 제공자 측정치도 아니다.
classify → Ledger.reserve/settle/blocked 경로로 확인했다. 완주 trace의 REQUEST_LIMIT은 73번째 admission을 거부한다는 뜻이다.
전체 모의 runner의 종료 이유는 ALL_SLOTS_ATTEMPTED이며 별도 프로세스 감사와 함께 제공한다.

| 슬롯당 합성 입력/출력 | 허용 슬롯 | 다음 admission 거부 |
| --- | ---: | --- |
| 1,000 / 100 | 72 | REQUEST_LIMIT |
| 1,000 / 8,192 | 18 | COST_LIMIT |
| 1,500 / 100 | 67 | INPUT_TOKEN_LIMIT |
| 100,001 / 0 | 1 | INPUT_TOKEN_LIMIT |
| 400,000 / 8,192 | 1 | INPUT_TOKEN_LIMIT |
| 0 / 8,192 | 18 | COST_LIMIT |

경계도 확인한다: 과거 입력 100,000은 허용/100,001은 거부, 과거 출력 581,632는 허용/581,633은 거부,
과거 비용 663,136,000 nano-USD는 허용/그보다 1 큰 값은 거부다. 최종 출력 한도는 72개가 모두 최대 출력일 때
정확히 충족하지만 현재 비용 gate가 그 전에 막을 수 있다.

## 후속 후보 예산과 필요한 변경 — 제안만

| 검토안 | 코드 비용 cap | 입력 누적 cap | 해석/필요 변경 |
| --- | ---: | ---: | --- |
| 현재 유지 | US$1.00 | 500,000 | 현재 구현 그대로. 72개 완료 보장 없음 |
| 비용 여유 후보 | US$3.03 | 500,000 | 별도 계획 버전·검토·승인 필요. 입력 시작 직전 100,000 gate는 그대로여서 완주 보장 없음 |
| 코드 허용 극단을 모두 수용하는 이론 후보 | 최소 US$24.254208; 반올림 후보 US$24.26 | 28,800,000 | 비용·입력 한도 변경과 새 버전·정책·검증·승인이 필요. 요청/출력/상황/순서는 그대로 |

참고용 독립 산술 trace에서 US$3.03/500,000 계획은 합성 1,000/8,192에서 72슬롯을 수용하지만,
1,500/8,192에서는 67슬롯에서 입력 gate가 막고 400,000/8,192에서는 1슬롯만 허용한다.
US$24.254208/28,800,000에서는 400,000/8,192 극단 모의 trace의 72슬롯이 gate를 통과한다.
이 trace는 실제 ProbePlan에 허용한 설정이 아니다. 현재 구현은 두 예산/한도 변경을 여전히 거부한다.

US$3.03은 입력 gate가 충족되는 자료에 비용 여유를 주는 검토 후보이며 권장 지출 승인으로 해석하지 않는다.
극단 후보는 추정 입력치를 상한으로 둔 설계가 아니라 기존 코드의 요청별 보수적 상한을 72번 적용한 산술이다.
그만큼의 입력을 실제 모델에 보내겠다는 뜻도 제공자 context 수락을 보장한다는 뜻도 아니다.

과거 확인 비용 US$0.12045585와 유지 조건부 예약 US$0.336864도 후속 누적 노출 검토에서 빠뜨리지 않는다.
그 합 US$0.45731985를 포함하면 US$3.03 후보의 조건부 계획 노출은 US$3.48731985,
US$24.26 후보는 US$24.71731985다. 모두 외부 청구의 무조건 상한이나 과거 비용 확정액이 아니다.

## 실제 실행 전 남은 조건

미확정 회계 정책과 과거 이력을 연결하는 방식의 검토·필수 지적 해소가 먼저다.
그 다음 정확한 새 source/계획/전체 이력/예산을 결합한 별도 실행안과 사용자 승인이 필요하다.
가격·신원·usage 조건이나 입력 gate가 달라지면 계산과 승인안도 다시 검토한다.
프롬프트 축약, 상황/반복 삭제, 성공 요청 재사용이나 추가 API token 측정으로 예산을 맞추지 않는다.
