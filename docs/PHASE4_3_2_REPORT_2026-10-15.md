journal, audit_snapshot, usage, engine 기록을 유지하고 hash/count도 다시 계산하지 않았다.

| 반례 | 수정 전 memory / CLI | 수정 후 memory / CLI |

| READY에서 raw=null, status=PENDING | 감사 성공 / exit0 | ValueError / exit1 |
| READY에서 raw=null, status=ERROR, error=UNRECORDED_ERROR | 감사 성공 / exit0 | ValueError / exit1 |

## 최소 변경과 유효 경로

runtime 변경은 `src/journeymap/experiments/paid_audit.py` 하나다.
OWNER_PACKET 처리에서 RESPONSE_DELIVERY 존재와 call.raw 존재를 양방향 대조하고,
성공 전달의 journal 원문으로 생성한 Record와 정확히 비교한다. late 폐기에도 적용한다.
OWNER_PACKET=READY는 성공 전달과 non-late를 요구한다. 최종 검사도 packet에서 시작해
분류가 없으면 READY, 실패 분류면 기록된 오류와 ERROR, 성공 분류면 기존 접수·완료
상태를 요구한다. 변조된 call.raw/status를 검사의 진입 조건으로 사용하지 않는다.

미회수 성공 응답은 journal에 전달 행이 있어도 raw가 없는 PENDING 상태로 유지할 수 있다.
기존 미전송/HTTP/usage/identity 실패도 성공 전달과 구분한다. 누락 원문을 채우거나
일괄 복구하지 않는다. FINISHED/UNCERTAIN 및 outcome_certain의 기존 의미는 유지한다.
메모리와 저장 replay는 기존의 동일 validator를 사용한다.

새 `tests/test_paid_audit_response.py`는 네 반례, owner 미회수 성공 응답, raw가 있는
refusal/incomplete의 PENDING 상태 변조 등 **7개**를 검증한다. 기존 test_paid_audit.py에는
owner 미회수 fixture 경로만 추가했다. 기존 테스트의 기대값은 변경하지 않았다.
새 verifier/packager와 [현재 응답 감사 계약](PHASE4_3_2_RESPONSE_AUDIT.md)을 추가하고
README, API, ARCHITECTURE, ERD, ROADMAP, TEST_STRATEGY와 .gitignore를 갱신했다.
엔진, prompt/schema, HTTP adapter/계획/가격, UI 및 기존 연구 adapter는 변경하지 않았다.
